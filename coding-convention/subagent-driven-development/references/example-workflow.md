# Delegated Development Example

This illustrative sequence shows evidence handoffs. Its labels and numbers are not actual results.

1. The response model reads the accepted plan, retains each task and establishes the permitted checkout and write scope.
2. The first delegate receives the complete hook-install task and asks whether installation is user-level. The response model answers from the accepted user-level requirement.
3. That delegate returns the diff, exact regression output, original evidence locator and accessed paths. The status label alone does not complete the task.
4. A delegate reviewing specification compliance inspects the code and maps user-level placement and required flags to source and test evidence.
5. A delegate reviewing code quality inspects the same target after specification compliance. The response model resolves valid blocking findings and marks the task complete only after both reviews are supported.
6. For the second task, specification review finds missing required progress reporting and an unrequested output flag. The delegate implementing that task corrects those behaviors; the delegate reviewing specification compliance checks the changed conditions.
7. The delegate reviewing code quality suggests extracting the reporting interval. The response model evaluates whether this is a real requirement or advisory style preference rather than treating every suggestion as blocking.
8. After all tasks satisfy their criteria, the response model obtains combined review and invokes finishing-a-development-branch for the authorized integration choice.

Verification-before-completion governs final claims.
