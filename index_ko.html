Ghost-ALICE OS

Claude Code와 Codex를 위한 거버넌스 계층입니다. 코딩 에이전트에게 사용자의 목적을 지키고, 각 주장을 원본 증거와 대조하고, 무엇을 건드렸는지 보여 주라고 지시합니다.

상한이 아니라 하한

코딩 에이전트는 흔한 방식으로 실수합니다. 긴 세션의 앞부분에서 정한 제약을 잊고, 확인하기 전에 성공했다고 보고하고, 요청받지 않은 일까지 합니다. 사용자는 에이전트가 무엇을 건드렸는지 쉽게 알 수 없습니다. Ghost-ALICE는 에이전트의 작업이 받아들일 수 있는 품질의 하한 아래로 떨어지지 않게 하려고 만들었습니다. 가장 숙련된 사용자가 이미 할 수 있는 일의 상한을 올리려는 도구가 아닙니다. 설계 원칙 읽기

Ghost-ALICE가 에이전트에게 지시하는 일

요청을 어떻게 읽었는지 기록합니다

도구를 쓰기 전에 에이전트가 요청을 해석한 내용, 곧 목적·제약·완료 조건을 기록합니다. 사용자의 말에 빈 곳이 있고 에이전트의 짐작이 다음 행동을 바꾸면 먼저 묻습니다.

설계 원칙

주장을 증거와 대조합니다

각 주장은 원본 증거와, 전체 답변은 사용자의 목적과 대조합니다. 필수 기준을 뒷받침하지 못하면 완료를 주장하지 않고 그 기준을 미해결로 알립니다.

검증과 증거

선언한 경계 안에서 일합니다

구현 작업 전에 건드려도 되는 곳과 안 되는 곳, 완료 기준, 멈추는 조건을 선언합니다.

경계 계약

건드린 것을 보여 줍니다

아직 내리지 않은 결정에 쓸 정보를 얻으려고 도구를 부르기 전에 무엇을 왜 하는지 밝힙니다. 답변에서 핵심 변경과 그 내용을 보여 주고, 에이전트의 도구 호출은 훅이 감사 기록에 남깁니다.

작동 방식

Ghost-ALICE Core는 공용 계약, 스킬, Core 코드(훅, 원장, 문맥 게이트웨이)로 이뤄집니다. 어댑터가 Core를 Claude Code나 Codex의 형식으로 변환하고, 인스톨러가 그 결과를 해당 호스트에 설치합니다. 에이전트는 Core의 지시를 따르고 자기 결과를 판단하며, Core 코드는 에이전트가 제출한 기록을 저장하고 그 기록과 원본 연결을 인증합니다. Ghost-ALICE는 사용자의 지시와 설치된 계약을 따르는 협조적인 모델을 전제로 설계했으며, 지시하고 기록할 뿐 Core 코드는 도구나 답변을 막지 않습니다.

Core 아키텍처 읽기구조의 경계

애드온

애드온은 bash install.sh --addon-source <저장소-또는-경로>로 자체 저장소나 로컬 경로에서 설치합니다. Core는 애드온의 스킬과 관찰 훅을 등록합니다. 그 훅은 호스트를 막지 않고, 설치만으로 실행 권한이 생기지 않습니다. 애드온이 더하는 기능은 애드온 자체 문서가 설명합니다.

설치와 업데이트

문제 해결

상태 확인과 진단 방법, 병합 대기와 훅 로딩 문제의 해결 방법을 안내합니다.

제거

사용자 파일은 남기고 Ghost-ALICE 소유로 기록된 설치 항목만 제거하는 방법을 안내합니다.

의도, 작업 선택, 완료 증거와 응답 범위를 설명합니다.
