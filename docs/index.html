Core operation

The response model compares the objective with original sources and selects the needed work. Judgment focus can be micro, meso, macro or meta. The work's verification burden sets its complexity level; beyond the level's own check, another check runs only when its outcome can change the next action.

Necessary long originals and answers remain available. Ghost-ALICE handoffs carry the current conclusion, unresolved conditions and original location needed for the next decision. The model retrieves the original when required. Earlier native messages can still enter subsequent requests; an installed adapter applies supported content selections. Original retention, handoff selection and actual request changes are separate.

When evidence conflicts with a required result, the response model selects a needed correction or investigation. It exposes unresolved conditions and reuses unchanged evidence at its original verification time.

Addons

An addon is installed from its own repository or a local path with bash install.sh --addon-source <repository-or-path>. Core registers the addon's skills and observational hooks; those hooks never block the host, and installation grants no run authority. The addon's own documentation describes what it adds.
