How it works

A quality floor, not a fixed script. Discretionary checks must discriminate a named uncertainty and map attainable outcomes to different next decisions. Mandatory checks remain required.

Session intake feeds task-router directly. Tool-checkpoint records and deduplicates retry guidance; native tool permission belongs to the host. SQLite and public ledger APIs own runtime state. JSON supplies validated import/export formats.

A new input rebinds the request, preserving unchanged proof. A first recording-only failure gets bounded repair; the identical unchanged failure parks until relevant change. Independent approved work continues. Business result, recording/application, whole-unit completion and delivery stay distinct.

A failed repair round requires corrective change and a completed relevant observation of the same unresolved failure. Initial failure is zero; the first-five checkpoint remains addressed across handoffs. Reassessment cannot reset attempts or resources. Unavailable required proof remains unverified; recording recovery preserves its stricter unchanged-failure park rule.
