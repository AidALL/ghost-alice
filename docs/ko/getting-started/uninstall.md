# 설치 제거 절차

[🇺🇸 English](../../getting-started/uninstall.md) | [🇰🇷 한국어](./uninstall.md)

제거 명령은 인스톨러가 작성한 `install-state` 매니페스트를 읽습니다. 인스톨러가 설치하거나 변경했다고 기록한 항목만 제거하거나 복원합니다.

## 제거 범위 선택

| 목표 | 실행 명령 | 참고 |
| --- | --- | --- |
| Ghost-ALICE 관리 대상 전체 제거 | `bash install.sh --uninstall` | 기록된 대상 전체를 제거합니다 |
| 한 플랫폼 제거 | `bash install.sh --platform codex --uninstall` | 다른 플랫폼의 설치는 유지합니다 |
| 선택한 스킬 제거 | `bash install.sh --platform codex --uninstall task-router` | 다른 스킬이 남으면 훅과 공유 파일을 유지합니다 |
| 애드온 하나 제거, Core 유지 | `bash install.sh --platform codex --uninstall --addon <addon-id>` | 애드온의 훅을 먼저 해제하고 검증된 전용 파일을 제거합니다 |

개별 애드온 제거와 선택한 스킬 제거는 범위가 다릅니다. Core 갱신은 기존 애드온을 유지하며, 명시적인 애드온 제거 명령이 제거 범위를 선택합니다. 전체 제거는 설치된 애드온의 부속 기록을 포함한 활성 관리 대상을 정리하면서 원래 복구 사본과 로컬 근거는 보존합니다. 개별 애드온을 제거하면 Core와 다른 애드온의 설치는 유지합니다. 선택한 스킬을 제거할 때는 기존 의존성 확인이 설치된 애드온에 필요한 Core 스킬을 보호합니다.

## 기본 명령

플랫폼을 지정하지 않으면 제거 명령이 관리 대상 전체를 제거합니다.

```bash
bash install.sh --uninstall
```

```cmd
.\install.cmd --uninstall
```

플랫폼을 지정하면 제거 명령이 해당 플랫폼의 관리 대상만 제거합니다.

```bash
bash install.sh --platform codex --uninstall
```

```cmd
.\install.cmd --platform codex --uninstall
```

특정 스킬만 제거하려면 플랫폼과 스킬 이름을 함께 지정해 주세요. 다른 Ghost-ALICE 스킬이 남아 있으면 제거 명령은 훅과 `_shared`를 유지합니다.

선택 제거는 제품군 이름을 실제 하위 스킬로 확장하고 제품군과 각 하위 스킬의 의존성을 함께 확인합니다. 전체 제거와 같은 소유권 분류기를 사용하고, 대상을 삭제하기 전에 전체 제거 계획을 게이트웨이에 전달하며, 제거를 마쳤거나 대상이 없는 행만 목록에서 지웁니다. 기록된 목록과 소스에서 확인한 설치 스킬 중 어느 쪽에라도 남은 스킬이 있으면 공용 자산을 유지합니다.

```bash
bash install.sh --platform codex --uninstall task-router
```

```cmd
.\install.cmd --platform codex --uninstall task-router
```

## 기준 파일

인스톨러는 플랫폼별 매니페스트를 다음 위치에 기록합니다.

- `~/.ghost-alice/install-state/claude.json`
- `~/.ghost-alice/install-state/codex.json`

제거 명령은 매니페스트의 `targets`와 `system_env_changes`를 조회합니다. 매니페스트가 없거나 손상되었다면 인스톨러는 삭제 범위를 추측하여 넓히지 않고 인간 사용자가 검토하도록 그 항목을 보고합니다.

## 제거 순서

제거 명령은 선택한 제거 범위에 대해 다음 단계를 순서대로 실행합니다.

1. 전체 또는 플랫폼 제거에서는 해당 플랫폼의 설치된 애드온부터 제거합니다. 제거 표시를 기록하고 정확히 소유한 애드온 훅 등록을 해제한 뒤 검증된 전용 파일을 제거합니다. 호스트의 훅 설정 변경이 실패하면 파일과 부속 기록을 남깁니다. 수정된 대상과 부속 기록·제거 표시는 검토 또는 재시도를 위해 유지하며 재시도는 해제한 훅을 복구하지 않습니다.
2. 제거 루트가 등록된 문맥 게이트웨이의 런타임(`~/.ghost-alice/runtime/current`, 그 아래 또는 그 위 폴더)이나 서비스 파일 중 하나이거나, 제거가 Codex 전체 제거이면 Core 훅이나 파일을 변경하기 전에 해당 게이트웨이를 분리합니다. 설치 기록의 `service` 섹션이 서비스 파일을 지정합니다. 서비스 부재를 확인한 뒤 소유한 launch agent와 provider 블록을 제거하고 `service` 섹션을 삭제하며, 주변의 현재 사용자 설정, 상태 디렉터리, 구성 요소 로그와 기존 복구 자료는 유지합니다. Codex 구성이나 게이트웨이 서비스·상태 파일 자체가 심볼릭 링크이거나, 서비스 파일이 인스톨러 밖에서 변경되었거나, 해제 결과를 확인할 수 없으면 뒤따르는 Core 제거 작업을 실패로 중단합니다. Claude 제거나 선택한 Codex 스킬 제거처럼 서비스의 코드를 변경하지 않는 제거는 게이트웨이를 실행 상태로 유지합니다. 링크는 가리키는 곳이 아니라 링크 자신의 경로로 판정합니다. `service` 섹션이 없으면 제거는 launchd에 조회하며, 적재된 게이트웨이 서비스의 프로그램이 제거 루트 안이면 검토를 위해 제거를 중지합니다.
3. Core 플랫폼 훅 설정과 Codex 부트스트랩 또는 전역 규칙의 관리 블록을 제거하면서 Ghost-ALICE가 관리하지 않는 항목은 유지합니다.
4. 소스 저장소의 공용 `core.hooksPath`는 마지막 호스트의 전체 제거에서만 복원합니다. 지금 값이 install-state가 설치가 작성했다고 기록한 값과 같을 때만, install-state가 기록한 설치 전의 값을 다시 작성합니다(설치 전 값이 없으면 설정을 삭제합니다). 다른 호스트의 install-state가 남아 있으면 그 호스트를 위해 값을 그대로 두고, 기록이 없는 값이나 설치 뒤에 바뀐 값도 그대로 둡니다. 그다음 기록된 기능·신뢰 설정의 복원 조건을 적용합니다.
5. 허용된 루트 안에 있고 소유권 표시나 해시로 검증된 매니페스트 대상만 제거합니다. 다른 플랫폼의 설치 상태 매니페스트가 남아 있으면 공용 런타임과 훅 실행 파일은 유지합니다.
6. 선택한 플랫폼의 병합 대기 원본을 보존한 뒤 활성 대기열을 제거합니다. 다른 플랫폼이 설치돼 있으면 공용 설치 복구 사본은 유지하고, 마지막 플랫폼이면 먼저 보존합니다. 각 사본은 `~/.ghost-alice/uninstall-backup/<platform>/support-state/` 아래 새 디렉터리에 저장되며, 보고서 항목은 그 사본의 경로를 `backup_path`에 기록합니다. 원래 수정 시각과 심볼릭 링크 표현을 유지하고 기존 사본도 보존합니다. 복구 자료의 루트를 제거하기 전에 최상위·내부 링크 각각의 보존 사본 수정 시각을 수집한 원본 시각과 비교합니다. 링크 시각을 보존할 수 없으면 원본 루트와 설치 상태 매니페스트를 검토 대상으로 남깁니다. Windows junction을 포함하는 복구 자료는 자동으로 복사하거나 삭제하지 않고 보존합니다.
7. 나머지 인스톨러 지원 기록을 삭제하되, 지원 기록 삭제와 복구 사본 보존이 성공할 때까지 설치 상태 매니페스트를 유지합니다. 결과 보고서는 `~/.ghost-alice/uninstall-reports/` 아래에 작성합니다. 이 폴더에 남기는 보고서 수는 [런타임 상태 보존](../reference/repository-structure.md#런타임-상태-보존)이 정합니다.

제거 명령은 보존 사본 디렉터리, 최근 제거 보고서, 소스 체크아웃, 대화·세션 근거, 의도 원장과 `~/.ghost-alice/secrets.env` 같은 개인정보를 담은 로컬 파일을 삭제하지 않습니다. 영구 보존한다는 뜻은 아닙니다. Ghost-ALICE가 설치되어 있는 동안에는 [런타임 상태 보존](../reference/repository-structure.md#런타임-상태-보존) 규칙이 이 자료에 따로 적용됩니다. 설치 기록 `~/.ghost-alice/installed-payload.json`과 `~/.ghost-alice/rollbacks/` 아래의 배치 폴더는 두 호스트가 공유합니다. 한 호스트의 전체 제거는 다른 호스트를 위해 둘을 남기고(`manual-review`, `shared-support-in-use-by-other-platform`), 마지막 호스트의 전체 제거가 배치 폴더를 `~/.ghost-alice/uninstall-backup/<platform>/support-state/`에 보존한 뒤 둘을 제거합니다. `~/.ghost-alice/io-trace.jsonl` 같은 실행 감사 기록은 설치 대상이 아니라 로컬 감사 기록입니다. 실행 연결을 제거해도 자료 전체를 삭제하지는 않습니다. 이 설정·파일 결과만으로는 실행 중인 호스트가 변경을 적용했는지, 이미 전달된 작업이 취소됐는지 확인하지 않습니다. 독립 정리 CLI를 `--apply`나 그 별칭 `--confirm` 없이 실행하면 정리를 미리 봅니다. 설치·설정·복구 자료는 변경하지 않지만 결과 보고서는 작성합니다.

## 복구 원칙

정리 보고서를 읽을 때 스키마 버전 `2`, `mode=apply`, `<platform>-apply-<stamp>.json`은 제거를 적용한 실행의 출력으로 해석해 주세요. 과거 버전 `1` 보고서는 같은 실행 모드에 `mode=confirm`과 `<platform>-confirm-<stamp>.json`을 썼으며, 어느 이름도 인간 사용자의 확인을 기록하지 않습니다. 독립 정리 CLI는 `--apply`를 사용하고 `--confirm`을 별칭으로 계속 받습니다. 둘 다 없으면 정리를 미리 보고 보고서를 작성합니다. 애드온 제거는 기본으로 적용하며, `--dry-run`이 두 적용 별칭보다 우선합니다.

현재 분류기는 관리 대상에 외부 변경이 있으면 `externally-modified-managed`를 기록합니다. 외부 변경은 설치 뒤 인스톨러가 찾은, 인스톨러의 기록에 없는 변경이며 인스톨러는 변경한 주체를 기록하지 않습니다. 관리 기록이 항목을 소유하지 않으면 `unclaimed`를 기록하며, 이 상태는 삭제를 허용하지 않습니다. 과거 보고서나 병합 대기 항목을 읽을 때 `user-modified-managed`는 `externally-modified-managed`, `user-owned`와 진단의 `owner=user`는 `unclaimed`, `user-modified-purge`는 `external-change-purge`, `user-modified-quarantine`는 `external-change-quarantine`, `retired-managed-user-changes-preserved`는 `retired-managed-external-changes-preserved`로 해석해 주세요. 이 이름들은 분류와 보존 상태를 나타내며 변경한 주체를 뜻하지 않습니다. 이름을 바꾸려고 과거 항목, 백업 경로, 해시나 기록된 결과를 다시 쓰지 마세요. 제거 명령과 진단 명령은 현재 대상을 다시 분류합니다.

개별 애드온 제거는 파일을 삭제하기 전에 인스톨러가 Claude Code 설정에 추가한 `Skill(...)` 허용 규칙과 Codex의 소유한 훅 신뢰 설정을 해제합니다. 인스톨러의 Claude Code 허용 규칙 소유권은 설정 파일과 매니페스트가 선택한 스킬 이름에 결합됩니다. 기존 규칙, 이 인스톨러가 추가하지 않은 나중의 중복 규칙과 소유권을 모르는 이전 규칙은 보호합니다. Codex의 남은 훅 신뢰 항목은 같은 명령이 반복돼도 각 훅의 실제 그룹·핸들러 위치를 따릅니다. 인스톨러는 Ghost-ALICE가 설치하지 않은 훅의 신뢰 항목과 그 필드·주석을 보존하며, 작성한 주체를 기록하지 않습니다. 대상 위치의 충돌을 해결할 수 없으면 제거를 중단합니다. 설정 저장은 심볼릭 링크를 유지하고 원자적으로 교체합니다. 이어지는 훅 설정 저장이 실패하면 원래 신뢰 설정의 내용과 수정 시각을 복구합니다. 복구 자체가 실패할 경우에도 원래 설정의 보존 사본을 남깁니다.

Claude 권한 귀속 기록은 `addon-permissions/claude-v2.json`(스키마 `2`)을 사용합니다. 새 파일이 없으면 작성기는 이전 `claude.json`을 읽고, 별도 파일명에 새 스키마를 쓴 뒤 이전 파일을 고유한 `.bak` 이름으로 보존합니다. 규칙을 제거하기 전에 제거 대기 상태의 지문을 기록합니다. 설정은 저장했지만 귀속 기록은 저장하지 못한 경우 재시도는 끝난 설정 효과를 알아보고 다른 중복 규칙을 제거하지 않은 채 기록만 마칩니다. 현재 설정 지문이 다르면 검토 대상으로 남깁니다.

애드온 제거 CLI는 오류나 부분 제거에 종료 코드 `2`를 반환하며, 중단된 제거의 재개 오류도 포함합니다. 종료 코드 `1`은 애드온을 찾지 못한 경우입니다. 수정된 대상의 보존, 불명확한 권한 소유권이나 설정 오류를 완전한 제거로 계산하지 않습니다.

- 제거 명령은 기록되지 않은 사용자 설정의 복원 방법을 추측하지 않습니다.
- Ghost-ALICE 소유권 표지가 없는 스킬이나 파일을 자동 삭제하지 않습니다.
- 다른 플랫폼의 매니페스트가 같은 대상을 참조하면 파일을 유지하고 `manual-review`로 표시합니다.
- 없는 파일과 이미 정리된 설정은 실패로 처리하지 않고 `missing` 또는 `unchanged`로 보고합니다.

## system_env_changes

`system_env_changes`는 인스톨러가 적용한 환경 변경 목록입니다. 제거 명령은 항목에 `before`/`after` 값이나 복원 메타데이터가 있을 때만 해당 변경을 복원합니다.

인스톨러는 `source_repo_hook_path`, `codex_hooks_feature_flag`, `codex_project_trust` 변경을 기록합니다. 각 종류에 해당하는 제거 처리기와 기록된 복원 조건이 있습니다.

개발자는 새 `kind`를 추가할 때 `installer_update/install_state_schema.md`를 먼저 갱신하고 설치 기록과 제거 복원 테스트를 모두 추가합니다.
