# 도구 출력의 의미

Language: [🇺🇸 English](../../policies/tool-output-semantics.md) | 🇰🇷 한국어

도구 결과는 관찰·인증된 검토·실행한 동작을 구분합니다. 표시 문구는 이해를 돕고, 문서화된 기계 필드는 소비 코드의 판단을 관리합니다. 호환성 표시가 그 필드를 대신하지 않습니다.

## 호스트와 훅의 책임

네이티브 호스트는 도구 인자를 검증하고 권한을 적용합니다. 보고된 인자 오류에 따라 승인된 호출의 인자를 수정합니다. 거버넌스 훅은 작업 권한과 근거를 확인하며 직렬화된 문자열에서 도구 능력을 추측하지 않습니다.

훅 상태는 일치하는 설치·설정 불일치·비활성화·누락·미지원 플랫폼을 구분합니다. 불일치가 있으면 영향받은 설치 연결을 확인하며 모든 훅이 없다고 해석하지 않습니다. [플랫폼 호환성 계약](installer-platform-compatibility-matrix.md)은 설치 판단을 담당합니다.

개수는 선언한 단위를 유지합니다. 고유 발견 수와 물리적 등장 수는 다르며, 값이 없으면 미확인입니다.

## 검토·출력·계속 작업

응답 모델은 각 주장을 원본 근거와 비교한 뒤 답변 전체를 사용자 목적과 비교합니다. Core는 두 판단과 출처 연결을 인증합니다. 검토 영수증은 상태와 참조를 반환하며 답변 본문을 반복하지 않습니다. 모델은 검토한 원고를 네이티브 출력으로 제출합니다. 부정적인 검토나 누락된 선행 조건은 [검토 절차](../../../coding-convention/verification-before-completion/references/response-review.md)에 따라 미해결로 남습니다.

```mermaid
flowchart LR
  M["응답 모델: 주장과 답변 전체 판단"] --> C["Core: 연결 인증"]
  C -->|상태와 참조| M
  M --> H["네이티브 호스트: 답변 표시"]
  H -->|Stop 관찰| A["Autopilot: 적용 가능한 근거 반영"]
  A -->|승인된 작업 요청| H
```

수락된 답변도 미완료 작업을 정확히 보고할 수 있습니다. 인증·게시·기준 반영은 별개의 결과입니다. 변하지 않은 근거를 재사용할 때 원래 검증 시각을 유지합니다. 기록 실패가 업무 재실행을 승인하지는 않습니다.

네이티브 Stop은 응답을 관찰하고 기본 대화가 계속되도록 합니다. 진단 판정은 답변이 화면에 표시되었음을 입증하거나 누락된 판단을 만들지 않습니다. Autopilot은 수락된 계획에서 계속 작업을 선택하며 요청 반환은 전달이나 실행을 입증하지 않습니다. 책임은 [아키텍처](../../../architecture_ko.md)와 [세션 게이트 소유자 표](session-gate-matrix.md)를 참조해 주세요.
