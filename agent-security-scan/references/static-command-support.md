# Static command support

The response model reads this reference when interpreting hook-command findings or extending the scanner's command grammar. The scanner reports literal execution paths and conditional candidates from configuration text. It does not run those commands, establish that a host ran them, or establish that a reported path succeeded.

## Execution boundaries

| Input boundary | Scanner behavior | Required distinction |
| --- | --- | --- |
| Shell command positions | Track quotes, substitutions, separators, case patterns, loop headers, function headers and named coprocess bodies. | Words in data arguments and case patterns do not become commands. Function declarations expose potential body paths without proving invocation. |
| Direct argv launchers | Consume registered option operands, short clusters, attached values, long `=` values, `--`, fixed operands and supported subcommands. Pass views of the original token buffer to the child. | Values such as the account in `sudo -u ACCOUNT` are data. `command -v`, `sudo -l`, `doas -C`, help and version modes do not select the displayed child as a command. |
| Shell text | Parse explicit POSIX shell command operands, `eval`, trap handler, SSH remote command, `su -c`, tmux single shell-command, `nix-shell --run` and parallel command-template text. | `echo 'sh -c id'` remains echo data when that text is interpreted. Tmux multiple command arguments are direct argv. Other shell families' startup selection does not make their command operands POSIX source. |
| rsync remote shell | Split an explicit `-e`/`--rsh` operand into remote-shell argv when a remote operand is present. | rsync separates words with spaces, honors matching and doubled quotes, and does not interpret backslashes, tabs or shell operators as shell syntax. |
| Git SSH selection | Connect the selected command-local literal `GIT_SSH_COMMAND` or `git -c core.sshCommand=...` with a transport-capable Git command. The wrapper selector preserves literal appends to a known command-local value and applies `env` reset, unset and last-assignment operations, including supported `-S` splits, before delivering the value to Git. | An inherited unknown append remains unresolved and does not select the config fallback. `env GIT_SSH_COMMAND+=VALUE` assigns the distinct name `GIT_SSH_COMMAND+`; it is not a shell append. `git status` and assignments attached to another executable do not activate the SSH setting. An empty explicit environment value does not select the config fallback. The actual remote must use SSH. |
| Container launch | Traverse global options, `container`/`compose`, run/exec options and image/service/container operands. | An explicit entrypoint owns the executable position. `--entrypoint printf IMAGE sh -c id` passes data to printf. Image/service default entrypoints remain external facts. |
| Kubernetes launch | Read the actual `--` command delimiter after consuming option operands in exec/run/debug. | `run` without `--command` supplies image args. Debug supplies a command by default and supplies args with `--arguments-only`. |
| Static program input | Connect here-strings, heredocs, pipes, `/dev/stdin` and process-substitution output to an identified program-input consumer. | The last fd 0 redirection wins. Other descriptors and shell script-file stdin remain data. xargs transforms stdin into arguments; it does not forward that source as a shell program. |

Static producers are option-free literal echo arguments, printf with exactly `%s` or `%s\n`, and cat forwarding a known literal input. The source connector supplies only complete output: an unsupported multi-producer stream remains unknown instead of becoming the last producer's output. A newline after `|` preserves the pending pipe receiver. The scanner does not evaluate arbitrary formatters, `echo -e`, variable values, command-substitution output or external files. It still inspects command positions inside substitutions. Quoted heredocs used as cat data suppress their substitutions; a shell consuming that heredoc as program text interprets the supplied program. Transparent wrappers forward stdin. The container and Kubernetes selectors apply supported Boolean aliases in occurrence order: Docker exec requires interactive input, Compose defaults to it, and kubectl requires enabled stdin. Docker, Compose and Podman detach their local stdin in detached mode; nerdctl exec rejects combined interactive and detached modes. The scanner does not model nerdctl run's logging-dependent detached I/O. SSH without a remote command requires the remote default shell to read stdin.

## Shell families and PowerShell

The input-mode resolver distinguishes POSIX-style sh/bash/zsh/dash/ash/hush/ksh/mksh, csh/tcsh, fish, cmd and PowerShell entrypoints. It recognizes explicit command options without treating shell option values or script arguments as command options. A bare `-` or `--` with no script operand selects stdin; `bash - script.sh` selects a file. GNU Bash long options use their exact registered names, with a separate operand for `--rcfile` or `--init-file`; `--rcfile=VALUE` is invalid. The scanner leaves non-POSIX shell bodies uninterpreted for command, stdin and known file input alike. The shell invocation can still produce its own policy finding; its body does not produce POSIX descendants.

PowerShell 7 and Windows PowerShell 5.1 have separate ordered option specifications. A supported abbreviation must satisfy the upstream minimum prefix length and full-name prefix match. Exact aliases are separate entries. In PowerShell 7 the command selectors include command prefixes beginning at `c`, the full `CommandWithArgs` or exact `cwa`, and encodedcommand prefixes beginning at `e` or alias `ec`. Command and CommandWithArgs consume the remaining arguments; EncodedCommand consumes one operand and startup option parsing continues. File mode ends option interpretation; the same spellings after a script path are script arguments. PowerShell 7 version/help switches end startup. Windows PowerShell's `-Version` consumes a version operand.

`CommandWithArgs` requires PowerShell 7.4 experimental support or PowerShell 7.5-preview.5 and later. A finding for an unversioned `pwsh -cwa` reports that condition. An EncodedCommand finding identifies the option path; it does not certify that the Base64 argument decodes to a valid executable program. Regression tests include a valid UTF-16LE encoding of an inert Write-Output command as well as the preserved invalid `abc` input. These are scanner inputs, not PowerShell executions.

## Interpreter and gate selection

The interpreter selector consumes registered startup option operands for Python, Node, Ruby, Perl, PHP and osascript. It recognizes each interpreter's inline-code options and stops at a script, Python module, stdin marker or `--` boundary. Later arguments remain program data. Node's `--trace-warnings` consumes no operand. Ruby's `-W` consumes only an attached supported warning level or category, so bare `-W` leaves the following word untouched. An unregistered option leaves the program selection unknown rather than guessing its operand count. The selector does not inspect external scripts or implement every interpreter option; an unsupported startup shape is not a safe-execution judgment.

Hook policy recognizes `profile-gate`, `hook_profile_gate.py` and `ghost-alice-hook.mjs` in executable positions, and the Python and Node gate files in their selected script positions. A filename in a comment, ordinary argument or inline-code operand supplies no gate evidence. This recognition identifies a static invocation, not the gate file's identity, behavior or successful execution. Hook policy retains its command-level gate exception; recognition does not establish that every separate command in a compound program passed through that gate.

## Conditions in results

The two hook shell rules retain their severity and mitigation. Their messages describe a defined execution path. When the literal candidate's role depends on an external entrypoint, transport or shell, `details.execution_conditions` reports that condition on the finding. MCP package findings preserve the conditions of their selected package-launch candidates in the same field. The response model preserves those conditions when explaining the result.

`scripts/fixtures/hook-command-regressions.json` defines each expected rule set once and groups command inputs by that rule set and execution condition. Case IDs retain the exceptional rationales. An empty expected result whose rationale names an unsupported form records a model limitation, not a safe-execution judgment.

## Cost and deployment

The lexer completes command and input-source links before selection. The option consumer preserves ordered occurrences and the stopping state; the shared traversal streams each invocation and executable descendant as a `CommandVector`. Native MCP argv enters this traversal without shell tokenization. Each command node retains its terminal selection, whose input mode, program operand and execution conditions are determined once. Hook policy consumes the shared stream. MCP policy matches package actions against exact executable and argument tokens in that stream and uses its native root's terminal selection for container, shell and filesystem facts. Package action prefixes also generate the legacy unstructured-text matcher; versioned Python and pip executable names use the existing normalized `python` and `pip` aliases. The source connector and finding generator consume selected facts without reinterpreting command options. Direct child work preserves available input sources and a set of distinct conditions. This keeps xargs and noninteractive container stdin separate from their child argv.

An argv buffer owns immutable tokens, a prefix index for safe shell-text reuse and indexes of find payload terminators. Child argv ranges carry indexes into that buffer. Direct argv boundaries never stringify and re-lex the suffix. A shell-text boundary reuses a range only when joining its words cannot change token or command boundaries; otherwise it creates a new lexical source. find terminators use binary search over the shared index. Cost checks cover source and token copying, condition propagation and range selection for simple eval/find/SSH/container nesting; they do not establish linear interpretation of arbitrary repeatedly quoted shell programs.

The installed skill folder contains its own byte-identical distribution of the shared `codex_config_toml` package and unmodified Tomli 2.4.0 with its license. The scanner reads one initial UTF-8 BOM and TOML 1.1 through that syntax owner. The scanner replaces undecodable UTF-8 bytes before inspecting each selected file; observed coverage means that this decoded text was read and, for configuration, parsed. It does not certify the original bytes' UTF-8 validity. A configuration parse error leaves coverage unobserved. The scanner requires neither a repository checkout nor `_shared` at runtime; the copied-skill CLI tests clear Python path overrides and run outside the checkout.

## Grammar sources

The implementation uses the following command-position and operand contracts. A supported literal shape does not imply support for every option, implementation, version or native operating system of that tool. In particular, script's explicit file-before-command form is the BSD/macOS form, chrt tests provide an explicit priority, and runuser tests use its `-u` command mode.

| --- | --- |

This finite model does not resolve aliases, variables, script contents, implicit compose commands, image metadata, PATH contents, account shells or active locale catalogs. Podman and nerdctl Compose-provider I/O is not modeled by the Docker Compose attachment rule. Its env split-string support is limited to the modeled quoting forms; it does not implement every GNU escape, including `\_`. Missing native executables, privileges, network connections or remote targets limit execution claims; they do not remove an explicit literal candidate from the static result. The response model reports these limits rather than presenting a clean finding list as proof of safe execution.
